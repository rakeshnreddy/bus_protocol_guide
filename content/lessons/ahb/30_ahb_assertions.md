Simulation relies on checkers to automatically flag when a design violates the protocol. These are usually written in SystemVerilog Assertions (SVA) inside an interface monitor.

If any of these assertions fire during a test, the test must immediately fail, and the designer must fix the RTL.

## Critical Master Assertions

1. **Wait State Stability:** If `HREADY` is 0, the master MUST NOT change `HTRANS`, `HADDR`, `HWRITE`, `HSIZE`, or `HBURST` on the next clock cycle.
2. **Burst Legality (HTRANS):** A burst must always start with `NONSEQ`. Every subsequent beat must be `SEQ` or `BUSY`. It is strictly illegal for `HTRANS` to transition from `BUSY` directly to `IDLE` in the middle of a burst.
3. **Burst Address Progression:** For an `INCR` burst, the `HADDR` of a `SEQ` transfer MUST equal the `HADDR` of the previous beat plus the byte size specified by `HSIZE`.
4. **Wrap Boundary Enforcement:** For a `WRAP` burst, when the address reaches the calculated wrap boundary, the next `SEQ` address MUST wrap back to the lower boundary limit.

## Critical Slave Assertions

1. **Two-Cycle Error Protocol:** If a slave drives `HRESP = ERROR`, it MUST drive `HREADY = 0` in the first cycle, and `HRESP = ERROR` with `HREADY = 1` in the exact next cycle.
2. **Zero-Wait State IDLE:** If a master drives `HTRANS = IDLE`, the slave MUST respond with `HREADY = 1` and `HRESP = OKAY`. A slave cannot stall an idle cycle.
3. **Exclusive Okay Legality:** A slave MUST NOT return `HEXOKAY = 1` unless the master's transfer was initiated with `HEXCL = 1`.

By building a robust library of these protocol assertions, you ensure that any stimulus generated by your constrained-random VIP will instantly catch bad behavior.
